# Pricing-Tier Tag Auto-Tagging

## Single source of truth

`lib/llm_dispatch/config.py`:

```python
PRICING_TIERS: list[tuple[str, float, float]] = [
    ('cheap', 3.0, 15.0),     # input < $3/1M AND output < $15/1M (strict)
]
MANAGED_TIER_TAGS = frozenset(tag for tag, *_ in PRICING_TIERS)
```

Adding a new tier = append one row. Every consumer re-evaluates automatically.

## Public API

- `get_pricing_tiers(model_id, fallback_cost_per_1k=, input_price=, output_price=) -> set[str]`
  — returns all applicable tier tags. Empty set if no data.
- `is_model_cheap(...)` — backward-compat shim, just `'cheap' in get_pricing_tiers(...)`.
- `reevaluate_pricing_tags(models, log_prefix='')` — mutates `capabilities` lists in place,
  only touches tags in `MANAGED_TIER_TAGS`, skips image_gen/embedding, logs summary.

## Backend injection points (all use the helper)

| Location | Trigger |
|---|---|
| `routes/config.py::_reeval_cheap_tags` | every GET /api/server-config |
| `routes/config.py::get_provider_templates` | every GET /api/provider-templates |
| `lib/llm_dispatch/discovery.py::_infer_capabilities` | discover_models / probe_provider |
| `lib/llm_dispatch/discovery.py::enrich_models_with_pricing` | OpenRouter price enrichment |
| `lib/llm_dispatch/dispatcher.py::_build_slots_from_providers` + `_build_slots_from_env` | slot pool build |
| `routes/config.py::_build_default_providers::_auto_cheap` | first-boot defaults |

## Frontend defense-in-depth

`static/js/settings.js` has a mirror of the tier table and two helpers:
- `_PRICING_TIERS_JS = [['cheap', 3.0, 15.0]]`
- `_getPricingTiersJS(modelId, blendedCostPer1k)` — uses `_modelPricingCache`
  populated from `/api/server-config`'s `model_pricing` payload.
- `_normalizeModelsPricingTags(models)` — in-place cap normalization.

**Applied at**:
- `addProviderFromTemplate()` — when user clicks "add provider from template"
- `_syncFromTemplate()` — when user clicks 📋 同步模板 on existing provider

Reason: `_syncFromTemplate` writes `tm.capabilities` directly into the
user's provider list client-side, BEFORE the backend sees it. Without
the client-side re-eval the user sees a stale tag until they save +
reload. This was the root cause of the "deepseek-chat shown without
cheap even after restart" bug.

## Static rewriter

`debug/reeval_pricing_tags.py`:
- `--dry-run` — preview
- (default) — rewrite three targets:
  1. `static/provider_templates/*.json`
  2. `lib/llm_dispatch/config.py::DEFAULT_SLOT_CONFIGS` (caps sets)
  3. `static/js/settings.js::_PROVIDER_TEMPLATES` (capabilities arrays)
- `--check` — CI-friendly, exit 1 if stale
- Preserves original formatting (text-level regex edit of just the
  capabilities arrays). Never touches non-chat models (image_gen/embedding).
- Idempotent — second run reports 0 changes.

## CI

`.github/workflows/ci.yml` has a `pricing-tags` job (needs: lint) that
runs `python3 debug/reeval_pricing_tags.py --check`. Fails the build
if any committed caps drift from live MODEL_PRICING.

## Rules

- **Strict `<`**: input strictly below threshold (Sonnet at exactly $3/$15 is NOT cheap).
- **Non-chat models skipped**: image_gen / embedding caps never get tier tags.
- **Tag ownership**: `MANAGED_TIER_TAGS` is fully owned — stale tags are removed,
  missing tags added. Non-tier caps (text/vision/thinking) are never touched.
- **Blended cost fallback**: when only `cost` ($/1K) is present, uses midpoint
  threshold — symmetric pricing assumption. ≤ (input_max + output_max)/2 per 1M.
- **bundle-*.js**: auto-regenerated by `lib/js_bundler.py` on server start from
  `settings.js`, so rewriting `settings.js` is sufficient.
