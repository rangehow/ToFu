## 3. Design: blocks, attempts, order

- **Replicate block** = one native runner over all 30 tasks × {tofu, codex}, task-major (the runner's sorted task
  order interleaves DeepSWE and TB), concurrency 2 (both arms of a task run in the same window), one key.
  Arm order alternates by block (odd: tofu,codex; even: codex,tofu).
- **Attempts:** K = 5 replicate blocks are planned (`fhm-k1` … `fhm-k5`); **k1–k3 are the committed minimum (≥ 3
  attempts per task per arm)**. Blocks run in label order, k1 on 0733 and k2 on 6672 in parallel, then k3/k4, then k5.
  The number of blocks is not changed in response to outcomes; a block is cut short only by a §6 stop rule, and the
  report then states the completed K per task. Within a block, `--max-attempts 2` retries only unmeasured
  (infrastructure) outcomes; canonical cell = first valid attempt (FHE's own selection).
- **Smoke first (non-canonical, label `smoke-fhm-t4`):** tofu-T4 only, on regex-log, openssl-selfsigned-cert,
  sqlite-db-truncate, fastapi-deprecation-response-headers and python-statemachine-state-data-scoping. Gate G1 (§1)
  plus: every trial yields a scored outcome or the known pre-call crash; tiktoken egress denials ≤ 5 per trial.
- **Calibration** is the same-environment Codex arm of k1–k5 against FHE's published Codex row (§5). No separate
  calibration block is needed; FRONTIER-HARNESS-1's Codex blocks (C, A1, T, A2, B) are reported as secondary,
  descriptive calibration evidence only.

## 4. Scoring

- **Primary scorer: FHE's own `normalize-results.mjs` at e837a70, unchanged** (sha256 `9bbe392e…913f`), run per
  (block, arm) on the export of `evaluations.frontier_harness.export` (status rule: reward ≥ 1 with observed model
  usage = success; other reward with usage, or agent timeout after start = failure; everything else infra_invalid).
  Per-task canonical cells are read from its `candidate.json` `task_details`. Smoke labels are excluded by it.
- **Robustness variant (always co-reported): harness-fault-as-failure.** A cell that FHE marks infra_invalid only
  because the harness made no model call although the trial ran and the verifier returned a reward (native outcome
  `scored`) counts as a **failure**. Rationale: a deterministic harness crash is not infrastructure; FHE's rule would
  drop it from the denominator and favour the crashing harness.
- **Throttle sensitivity (always co-reported):** cells with any upstream 429 omitted (`exclude_throttled`). Throttled
  trials are never re-run to replace canonical cells.
- Cost: relay-metered usage priced at FHE's frozen Kimi K3 table (`pricing.json` kimi-k3-2026-08-20): a benchmark
  basis, not FRIDAY's bill.

## 5. Analysis and decision rules (script `evaluations/frontier_harness/multi_attempt.py`, committed with this file)

Let s_ai / n_ai be arm a's passes / valid cells on task i over the completed blocks.

1. **Arm pass rate** = mean over tasks with n_ai ≥ 1 of s_ai / n_ai (each task weighs 1, as in FHE). 95% CI:
   task-clustered percentile bootstrap (tasks resampled with replacement, 10,000 draws, seed 20261113). Also per suite
   (TB 21, DeepSWE 9) and per block (passes/valid with Wilson 95%).
2. **Tofu − Codex (primary comparison)** on tasks valid in both arms: d_i = s_Ti/n_Ti − s_Ci/n_Ci; estimate mean d;
   95% task-clustered bootstrap CI; two-sided paired sign-flip permutation test over tasks (exact when ≤ 20 tasks have
   d_i ≠ 0, else 200,000 random flips). **Decision:** "Tofu ahead" only if CI lower bound > 0 and p < 0.05; "Codex
   ahead" only if CI upper bound < 0 and p < 0.05; otherwise "not distinguishable at this sample". Suite-level
   differences are descriptive only. The same rule is applied to the robustness and throttle variants and all three
   are reported; the headline is the primary variant, with the others beside it.
3. **Calibration (our Codex vs FHE's published Codex v1 row, 20/30):** per task p̂_i = (s_Ci + 0.5)/(n_Ci + 1);
   under H0 (FHE's single attempt has our per-task success probabilities) FHE's total over the tasks valid in both is
   Poisson-binomial(p̂). Two-sided p = min(1, 2·min(P(T ≤ t_obs), P(T ≥ t_obs))). **"Consistent" iff p ≥ 0.05**, else
   "conditions differ". Secondary, for continuity with PREREG.md: block k1 alone, |Δ passes| ≤ 3 and exact McNemar
   p ≥ 0.05. Per-task agreement is tabulated.
4. **Standing (no rank beyond the evidence).** No ordinal rank number is ever stated.
   - Always: the same-environment Tofu − Codex result of rule 2.
   - Only if calibration is "consistent": an FHE-anchored estimate for Tofu = mean_i(y_FHE,Codex,i + d_i) (FHE's
     published Codex outcome per task plus our paired difference; assumes the environment shifts both harnesses
     alike), 95% CI by task bootstrap; the report lists the published v1 configurations whose published pass rate
     lies inside that CI ("not distinguishable from …"), always labelled `methodology_comparable=false`
     (non-Runta VMs, FRIDAY instead of Fireworks, our recorded allowlist vs FHE's unrecorded one).
   - If "conditions differ": unranked; report raw rates, coverage and cost only.

## 6. Stop rules (non-cost; the owner removed every spend gate on 2026-11-13)

1. **429 on a key:** the relay writes that key's stop file on the first upstream 429 (HTTP or in-stream); its runner
   starts no new trial; in-flight trials finish and are marked throttled. The bucket rests to the next full minute
   + 60 s; resume only after review, at half that key's rpm_max (eval-quota rule). Incident logged in
   `phase-m/incidents.jsonl` and eval-quota.json `incidents[]`.
2. **402/401/403 on any key:** stop that key's lane at once and report.
3. **Infrastructure:** a task infra_invalid twice in one block is reported; ≥ 3 infra-invalid cells in a block pause
   that block for diagnosis.
4. **Context leakage (G1):** any date/journal/UI-nav block in tofu-T4 first bodies stops the Tofu arm.
5. **Production protection:** no production writes, restarts or landings; relays/runners/guard detached at
   `nice -n 19`, started after `bin/memgate.sh`; all agent and verifier work runs in sandbox VMs; ≤ 2 concurrent trial
   VMs per key; relays stopped whenever no block runs (they are unauthenticated on 0.0.0.0).
6. **Spend:** none. Spend is reported per block (frozen-table USD per arm and key).

## Amendment 7 (2026-11-13, before any v1.1 trial; exact commit time in phase-m/PREREG-2.commit): relay rate-limit holds do not consume the agent budget (v1.1 primary)

Trigger: coordinator 71673c1d item 2. The proposal (`phase-m/amendment7-proposal/PROPOSAL.md`, message 617d2656) was
approved as written by coordinator cdcf67a4, with the conditions in items 8-11. No v1.1 outcome exists yet. From v1,
only the k1+k2 wait statistics that motivated this amendment are used. v1 (k1-k5) is unchanged.

1. **Problem.** Our provider quota makes the relay pace model requests: request and token windows at 50 % of the
   measured AppId limits. FHE's reference runs have no such limits. In k1+k2 (32 measured cells per arm at 20:06),
   every cell that hit its agent budget (Tofu 4, Codex 5) had relay waits in it. All 9 would have been inside the
   budget without them.
2. **Held seconds.** For each model request, the relay times the whole pass through its gates before going
   upstream: key cool-down after a 429, the request window, the token window, and the queue on their locks.
   - It logs the hold per call as `held_s`.
   - It keeps a running total per trial (arm, task), holds in progress included, rebuilt from its log at a restart.
   - It serves the total at `GET /arm/<arm>/task/<task>/held`.
   - Upstream generation, retries after upstream errors and everything outside the relay remain agent time.
3. **Deadline.** Agent deadline = agent start + the task's agent budget + H, where H is the trial's held total minus
   its value at the agent's start.
   - `vm_trial` re-reads H each time the deadline is reached. It stops the agent only when the latest H no longer
     moves the deadline past now.
   - While a request is held, H grows with the clock, so the deadline cannot fall inside a hold. During a hold the
     runner re-reads once a second, so the end of a hold is seen at most 1 s late.
4. **One enforcer.** The runner's deadline stops both arms the same way: SIGTERM to the agent's process tree, then
   SIGKILL after 30 s.
   - Codex has no timer of its own (unchanged).
   - Tofu's `--timeout-s` is set to the VM lifetime and its finalize grace to 0, so Tofu is stopped at the same
     deadline. Tofu's `timeout_s` only bounds its own result wait and never reaches the model or the agent core
     (732ace66).
5. **Backstops.** The host runner's trial deadline (phase budgets + 3600 s) moves by the same held total.
   - v1.1 blocks run with `--max-alive-min 480` instead of Amendment 2's 330. This covers sam-cell-seg's 302-min
     trial budget plus 178 min of holds.
   - A trial lost to the VM lifetime is an infrastructure failure (D-2) and is re-run.
6. **Failures.** If H cannot be read when the agent starts, the attempt is an infrastructure failure and is re-run.
   A read that fails 3 times, 2 s apart, keeps the last value. Each attempt records `relay_held_reads` and
   `relay_held_errors`, and the export flags every attempt with errors.
7. **Analysis.** The primary analysis is Amendment 2 item 7 applied to the v1.1 cells measured under protocol
   **`fhe-v11-hold`**:
   - pass rates per arm, scored by FHE's unmodified normalizer (Amendment 2 item 6);
   - section 5's intervals and decision rules, including rule 4 and the calibration against FHE's published Codex.

   Each attempt records `extension_s` (H at stop or exit), `stopped_at_s` (when cut) and `relay_held_base_s`.
   Co-reported per cell and per arm:
   - H;
   - H's share of agent wall time;
   - the agent's own time (wall − H);
   - the cells stopped at the extended deadline.
8. **Tofu's result document under SIGTERM.** For every Tofu cell cut at the extended deadline, record whether
