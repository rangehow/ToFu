# Rust MCP client

This crate is Phase 5 of `docs/RUST_REWRITE_EVIDENCE.md`: Tofu's MCP client
(`lib/mcp`) on rmcp. The product does not use it yet. The Python `lib/mcp`
package is the oracle, and the parity status and known differences are listed
in that document under "Phase 5 progress". When behaviour changes, change
Python first, then port it and rerun the parity suites.

## Modules

- `bridge.rs`: `call_tool` in the oracle's gate order, and the catalog index.
  Child modules share its state: `bridge/lifecycle.rs` (keepalive sweep, idle
  parking, `tools/list_changed`, reconnects and the breaker, connect and
  shutdown ordering), `bridge/credentials.rs` (probe state, renewal, the
  credential follow-up of `call_tool`), `bridge/catalog.rs` (generation
  projections).
- `callback.rs`: host-to-binding calls. State Python owns (route plan, stored
  rows, vault, browser devices, declarations, the registry catalog) is asked
  for, never copied; handlers live in `lib/mcp/rust_host.py`.
- `queue_policy.rs`: the owner Hope ban, which fails closed on the contract's
  `m17` entry.
- `stdio_env.rs`: the child environment. `launcher.rs` / `vendor.rs`: launcher
  self-heal, install jobs, vendored argv, pre-warm markers, npx reconciliation.
- `network.rs`: outbound HTTP through the shared network authority (plan and
  health from the binding, connect-only failover); `RoutedHttpClient` is
  rmcp's Streamable HTTP client. `updates.rs`: upstream version checks.
- `health_probe.rs`, `browser_credentials.rs`: the credential probe contract
  and browser-held credentials.
- `tool_search.rs`, `progressive.rs`, `connector_guidance.rs`, `registry.rs`:
  catalog search and selection, retired wrappers, connector guidance, the
  edition filter. `generated_pyunicode.rs` is generated by
  `scripts/gen_pyunicode.py` (`--check` is the drift test).
- `transport.rs`: templating and redaction. `result.rs`: result projection.
  `errors.rs`: failure categories.
- `relay.rs`: wire-compatible with `lib/runtime/loopback_relay.py`.
- `rmcp_session.rs`: the rmcp transports. `host.rs`: the JSON-lines protocol
  used by `lib/mcp/rust_host.py`.

## Rules

- Byte formats come from CPython. Use `pyjson.rs`/`pyos.rs`. Never use
  serde's defaults where a digest, a relay frame or display text depends on
  the format.
- Nothing is sized by the machine. That means one current-thread runtime, no
  blocking pool and no admission caps (the rmcp HTTP request cap is lifted).
- No tuning knobs: every interval, timeout and size is the oracle's constant
  or environment variable. Time-driven tests use host seams (`sweep_once`,
  `advance_clock`, `credentials.sweep`), never shortened intervals.

## Verify

Build with a `CARGO_TARGET_DIR` on local disk (`$TMPDIR`). Run the commands
under `nice -n 19 ionice -c3` while the host is loaded.

1. Run `cargo test`, `cargo clippy --all-targets -- -D warnings` and
   `cargo fmt --check`. `tests/recorded_session.rs` needs `python3`, or set
   `REPLAY_PYTHON`.
2. Run the Python parity suites, one file per process on a loaded host:
   `TOFU_MCP_HOST_BIN=<target>/debug/tofu-mcp-host PYTHONPATH=<repo> <repo>/.venv/bin/python3 -m pytest -q tests/mcp_protocol/test_rust_<area>_parity.py`,
   then `tests/mcp_protocol/test_rust_coverage_map.py`: every oracle file in
   `tests/mcp_protocol` must be named in some suite's `COVERS`. Without the
   variable, the suites build the binary with Cargo.
3. If the Python bridge's outcomes change on purpose, regenerate the golden
   file with `.venv/bin/python3 packages/tofu-mcp/scripts/gen_session_golden.py`.
